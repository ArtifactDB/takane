

# Genomic ranges (1.0)

## Overview

The `genomic_ranges` specification describes an on-disk representation of a genomic ranges.
Each entry of the genomic ranges defines the reference sequence, start coordinate, width and strandedness of an region on a genome.
It is based on the `GRanges` class from the [**GenomicRanges** Bioconductor package](https://bioconductor.org/packages/GenomicRanges).

To avoid confusion, "genomic ranges" will refer to the object represented by this specification, while "genomic regions" will refer to the entries of the genomic ranges.
For example, a genomic ranges might contain zero, one or multiple genomic regions.
Readers are advised to overlook the apparent error of referring to a singular object with a plural name.

## Object metadata

The `OBJECT` file should contain a `genomic_ranges` property, itself a JSON object with the following properties:

- `version`, a string specifying the version of the `genomic_ranges` format.
  This should be set to "1.0".

## Directory structure

### Contents

The directory should contain the following:

- `OBJECT`, a JSON file as described above.
- `sequence_information/`, a subdirectory.
- `ranges.h5`, a HDF5 file.

Optionally, it may also contain:

- `element_annotations/`, a subdirectory.
- `other_annotations/`, a subdirectory.

### `sequence_information/`

The `sequence_information/` subdirectory contains a child object that is a [_sequence information_](../sequence_information).
The number of reference sequences in the genomic ranges is defined as the number of sequences in the child sequence information.
A reference sequence is considered to be circular if the `sequence_information/circular` dataset in the `sequence_information/info.h5` file is non-missing and falsey.
The length of each reference sequence is similarly taken from the `sequence_information/length` dataset in the `sequence_information/info.h5` file.

### `ranges.h5`

The `ranges.h5` file should contain a `genomic_ranges` group.

The `genomic_ranges` group should contain the following datasets:

- `sequence`, an 1-dimensional dataset of any datatype that is representable by a 64-bit unsigned integer.
  Each entry is an index specifying the reference sequence (`sequence_information`) to which a genomic region is assigned.
  Thus, each entry should be less than the number of reference sequences.
- `start`, an 1-dimensional dataset of any datatype that is representable by a 64-bit signed integer.
  Each entry represent the 1-based coordinate of the start of the genomic region on its assigned reference sequence.
- `width`, an integer dataset of any datatype that is representable by a 64-bit unsigned integer.
  Each entry represents the width of the genomic region in base pairs.
- `strand`, an integer dataset of any datatype that is representable by a 32-bit signed integer.
  Each entry specifies the strandedness of the genomic region and should be one of -1 (reverse), 0 (unstranded) or 1 (forward).

The `genomic_ranges/sequence`, `genomic_ranges/start`, `genomic_ranges/width` and `genomic_ranges/strand` datasets should be of the same length.
The length of each dataset defines the number of genomic regions in the genomic ranges, where the $i$-th entry from each dataset describes the $i$-th genomic region.

For each genomic range, the value of `start + width` should fit in a 64-bit signed integer.
This supports alternative representations that store the one-past-the-end position of each genomic range.

If a reference sequence is not circular, all genomic regions assigned to it (based on the `genomic_ranges/sequence` dataset) should have positive `start`.
If a reference sequence is not circular and has a non-missing sequence length, all genomic regions assigned to it should have `start + width - 1` less than or equal to the sequence length.
If a reference sequence is circular, the starts of genomic regions assigned to it may be zero or negative.

Optionally, the `genomic_ranges` group may contain `name`.
This should be a 1-dimensional string dataset where the $i$-th entry contains the name of the $i$-th genomic range.
The length of this dataset should be equal to the number of genomic regions.

### `range_annotations/`

The `range_annotations/` subdirectory should contain a child object that satisfies the `DATA_FRAME` interface.
This child object should have number of rows equal to the number of genomic regions in the `ranges.h5` file.
The $i$-th row corresponds to the $i$-th genomic region and contains additional annotations for that genomic region.

If this subdirectory is absent, no additional annotations are available for the genomic regions in this genomic ranges.

### `other_annotations/`

The `other_annotations/` subdirectory should contain a child object that satisfies the `SIMPLE_LIST` interface.
This holds extra annotations for the entire genomic ranges. 

If this subdirectory is absent, no extra additions are available for this genomic ranges.

## Height

The height of a genomic ranges is defined as the number of genomic regions, as determined by the length of the datasets in the `genomic_ranges` group of the `ranges.h5` file.
