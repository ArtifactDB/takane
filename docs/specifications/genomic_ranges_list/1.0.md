

# Genomic ranges list (1.0)

## Overview

The `genomic_ranges_list` format provides an on-disk representation of a list of **genomic ranges**.
This is based on the `GRangesList` from the [**GenomicRanges** Bioconductor package](https://bioconductor.org/packages/GenomicRanges).

Here, the central idea is to store a single **genomic ranges** consisting of the concatenation of all entries of the **genomic ranges list**.
Each entry of the **genomic ranges list** is defined as a contiguous slice into this concatenated **genomic ranges**.
This avoids the storage overhead of multiple **genomic ranges** objects, which may be significant if each object is very small.

## Metadata

The `OBJECT` file should contain a `genomic_ranges_list` property, itself a JSON object with the following properties:

- `version`, a string specifying the version of the `genomic_ranges_list` format.
  This should be set to "1.0".

## Directory structure

### Contents

The directory should contain:

- `OBJECT`, a JSON file as described above.
- `partitions.h5`, a HDF5 file.
- `concatenated/`, a subdirectory.

Optionally, it may also contain:

- `element_annotations/`, a subdirectory.
- `other_annotations/`, a subdirectory.

### `partitions.h5`

The `partitions.h5` file should contain an `genomic_ranges_list` group.

The `genomic_ranges_list` group should contain a `lengths` dataset.
This dataset should be 1-dimensional and use a datatype that is representable by a 64-bit unsigned integer.
Each entry corresponds to an element of the **atomic vector list** (i.e., a single **genomic ranges** object),
and defines the number of consecutive elements in the `concatenated/` object that can be used to construct each **genomic ranges** object.

Optionally, the `genomic_ranges_list` group may contain `names`, a 1-dimensional string dataset of the same extent as `genomic_ranges_list/lengths`.
The $i$-th entry of this dataset contains the name of the $i$-th entry of the **atomic vector list**.

### `concatenated/`

The `concatenated` directory should contain a child object of the [`genomic_ranges`](../genomic_ranges) type.
The height of this child object should be equal to the sum of lengths in the `genomic_ranges_list/lengths` dataset of the `partitions.h5` file.
This child object represents the concatenation of all of the **genomic ranges** objects in the list.

The $i$-th entry of the **genomic ranges list** is constructed by taking the slice $[s_i, s_i + l_i)$ from the `concatenated/` object.  
$l_i$ is defined as the $i$-th entry of the `atomic_vector_list/lengths` dataset in the `partitions.h5` file.
$s_i$ is defined as the sum of $l_j$ for all $j < i$, or zero if $i = 0$.

### `element_annotations/`

The `element_annotations/` subdirectory should contain a child object that satisfies the `DATA_FRAME` interface.
This child object should have numberThis  of rows equal to the extent of the `genomic_ranges_list/lengths` dataset in the `partitions.h5` file.
The $i$-th row corresponds to the $i$-th entry of the **genomic ranges list** and contains additional annotations for that entry.

If this subdirectory is absent, no additional additions are available for entries of the **genomic ranges list**.

### `other_annotations/`

The `other_annotations/` subdirectory should contain a child object that satisfies the `SIMPLE_LIST` interface.
This holds extra annotations for the entire list.

If this subdirectory is absent, no extra additions are available for the **genomic ranges list**.

## Height

The height of the **genomic ranges list** is defined as the extent of the sole dimension of the `genomic_ranges_list/lengths` dataset in `partitions.h5`.
