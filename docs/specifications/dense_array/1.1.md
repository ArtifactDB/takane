

# Dense array (1.1)

## Overview

The `dense_array` specification describes an on-disk representation of a **dense array**.
This should have any positive number of dimensions and its type is either integer, boolean, floating-point or string.
It is based on the base arrays of the R programming language.

## Object metadata

The `OBJECT` file should contain a `dense_array` property, itself a JSON object with the following properties:

- `version`, a string specifying the version of the `dense_array` format.
  This should be set to "1.1".

## Directory structure

### Contents

The directory should contain the following:

- `OBJECT`, a JSON file as described above.
- `array.h5`, a HDF5 file.

### `array.h5`

#### General

The `array.h5` file should contain a `dense_array` group with the following attributes:

- `type`, a scalar string attribute specifying the type of the array 
  This should be one of `"integer"`, `"boolean"`, `"string"`, `"vls"` or `"number"`.

### Non-compressed VLS representation

For all `type != "vls"`, the `dense_array` group should contain `data`, an $N$-dimensional dataset where $N > 0$.
The datatype of this dataset depends on `type`:

- For `type = "integer"` or `"boolean"`, the datatype should be representable by a 32-bit signed integer.
- For `type = "number"`, the datatype should be representable by a 64-bit float.
- For `type = "string"`, a string datatype should be used.

Extents of zero for any dimension are allowed.

Optionally, the `dense_array/data` dataset may have a `missing-value-placeholder` scalar attribute. 
If present, all entries in the dataset equal to the placeholder value should be treated as missing.
The datatype of the attribute should be the same as `dense_array/data` if `type != "string"`; or any valid string datatype, if `type = "string"`.

#### Compressed VLS representation
    
For `type = "vls"`, the **dense array** consists of strings stored in the compressed variable length string (CVLS) format.
The `dense_array/data` group should contain: 

- `pointers`, an $N$-dimensional dataset using a compound datatype consisting of 2 members, `"offset"` and `"length"`.
  Each member should be of a datatype that can be represented by an unsigned 64-bit integer.
- `heap`, a 1-dimensional dataset of unsigned 8-bit integers.
  This contains bytes from all of the strings in the array, e.g., by concatenating all strings.

The $i$-th entry of the `dense_array/data/pointers` dataset refers to a slice $[o_i, o_i + l_i)$ of the `dense_array/data/heap` dataset,
where $o_i$ and $l_i$ are the values of the offset and length members, respectively.
This slice defines a variable-length UTF-8-encoded string, terminated at the first null in the slice.
If no null character is present within the slice, the string consists of the entire slice. 

Entries of the `dense_array/data/pointers` dataset may be sorted in any order and may refer to overlapping or non-contiguous slices.
The only requirement is that each $[o_i, o_i + l_i)$ slice lies within the boundaries of the heap dataset.

No restrictions are placed on the contents of the `dense_array/data/heap` dataset, as long as the strings can be recovered from slices as described above.
Writers of the `dense_array/data/heap` dataset may concatenate strings in arbitrary order, merge duplicate strings, add padding between strings, etc.
The heap may contain unused bytes, i.e., not referenced by any slice in the `dense_array/data/pointers` dataset.

Optionally, the `dense_array/data/pointers` dataset may contain a `missing-value-placeholder` scalar string attribute.
If this attribute is present, any strings in the CVLS array that are equal to the placeholder should be treated as missing.

#### Names

Optionally, the `dense_array` group may contain a `names` group.
This may contain any number of 1-dimensional string datasets named after the corresponding dimension of the `dense_array/data` dataset,
i.e., the `dense_array/names/{d}` dataset corresponds to the $d$-th dimension.
Each dataset contains the names for its dimension and should have length equal to the extent of that dimension.

Aside from the aforementioned datasets, no other objects should be present in the `dense_array/names` group.

#### Transposition

Optionally, the `dense_array` group may have a `transposed` attribute.
This should be scalar and its datatype should be representable by a 32-bit signed integer.
Any non-zero value indicates that the **dense array** is stored in a transposed format, i.e., the $d$-th HDF5 dimension is actually the $N-d-1$-th dimension in the **dense array**.
This is sometimes desirable for efficiently reading/writing from frameworks that use a different dimension ordering, e.g., column-major matrices versus HDF5's row-major layout.

If no `transposed` attribute is present, it is assumed to be false, i.e., no transposition. 

## Height

The height of the **dense array** is defined as the extent of the first dimension of the
`dense_array/data` dataset (for `type != "vls"`) or `dense_array/pointers` dataset (for `type == "vls"`)
in the `array.h5` file.
If the **dense array** is stored in a transposed format, the extent of the last dimension is used instead.

## Dimensions

The dimensions of the **dense array** are defined as the dimensions of the 
`dense_array/data` dataset (for `type != "vls"`) or `dense_array/pointers` dataset (for `type == "vls"`)
in the `array.h5` file.
If the **dense array** is stored in a transposed format, the dimensions are reversed.
