

# Multi-sample dataset (1.0)

## Overview

The `multi_sample_dataset` specification describes an on-disk representation of a multi-sample dataset.
It is based on the `MultiAssayExperiment` class from the [**MultiAssayExperiment** bioconductor package](https://bioconductor.org/packages/MultiAssayExperiment).

Briefly, a multi-sample dataset consists of multiple "samples" along with zero, one or more "experiments".
Each experiment is a summarized experiment or a summarized experiment-like object where each column of each experiment maps to a single sample.
The multi-sample dataset is mainly intended for large studies where one sample (e.g., patient) is subjected to multiple experiments.
Note that the definition of a "sample" here is unrelated to the concept of a sample in other specifications, e.g., [`spatial_experiment`](../spatial_experiment).

## Object metadata

The `OBJECT` file should contain a `multi_sample_dataset` property, itself a JSON object with the following properties:

- `version`, a string specifying the version of the `multi_sample_dataset` format.
  This should be set to "1.0".

## Directory structure

### Contents

The directory should contain the following:

- `OBJECT`, a JSON file as described above.
- `sample_data/`, a subdirectory.

Optionally, the directory may contain:

- `experiments/`, a subdirectory.
- `sample_map.h5`, a HDF5 file.
- `other_data/`, a subdirectory.

### `sample_data/`

The `sample_data/` subdirectory contains a child object that satisfies the `DATA_FRAME` interface.
The $i$-th row of this object describes the $i$-th sample of the multi-sample dataset.
Similarly, the number of rows in this object defines the number of samples. 

### `experiments/`

The `experiments/` subdirectory should contain a `names.json` file, which contains a JSON-formatted array of strings.
The $i$-th entry of this array contains the name of the $i$-th experiment of the multi-sample dataset.
The length of this array defines the number of experiments in the multi-sample dataset.
Strings should be non-empty and unique.

The $i$-th experiment experiment should be represented by the `experiments/{i}/` subdirectory.
Each subdirectory should contain a child object that satisfies the `SUMMARIZED_EXPERIMENT` interface.
The child object may have any number of columns, including zero.

Aside from `names.json` and the experiment subdirectories, no other files or directories should be present in the `experiments/` subdirectory.
The exception is that of files/directories prefixed with `.` or `_`, which are ignored.

If no `experiments/` subdirectory is present, the multi-sample dataset contains no experiments.

### `sample_map.h5`

The `sample_map.h5` file should contain a `multi_sample_dataset` group.

The $i$-th experiment in `experiments/` should be represented by a HDF5 dataset at `multi_sample_dataset/{i}`.
This dataset should have length equal to the number of columns of its experiment. 
The datatype should be representable by a 64-bit unsigned integer.

The $j$-th entry of the `multi_sample_dataset/{i}` dataset specifies the assigned sample for the $j$-th column of the $i$-th experiment. 
Each entry is a row index into the `sample_data/` child object.
Thus, each entry should be less than the number of rows in the `sample_data/` child object.

The `sample_map.h5` file may be missing if the `experiments/` directory is missing or contains no experiments.
However, if the `experiments/` subdirectory contains at least one experiment, a `sample_map.h5` file should also be present.

### `other_data/`

The `other_data/` subdirectory should contain a child object that satisfies the `SIMPLE_LIST` interface.
This holds extra annotations for the entire multi-sample dataset.

If this subdirectory is missing, no extra annotations are present in the multi-sample dataset.
