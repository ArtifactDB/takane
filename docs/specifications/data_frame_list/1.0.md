

# Data frame list (1.0)

## Overview

The `data_frame_list` specification describes an on-disk representation of a list of `DATA_FRAME`-compatible objects,
where each object contains the same type and order of columns.
This is based on the `CompressedSplitDataFrameList` from the [**IRanges** Bioconductor package](https://bioconductor.org/packages/IRanges).

Here, the central idea is to store a single `DATA_FRAME`-compatible object consisting of the concatenation of all entries of the **data frame list**.
Each entry of the **data frame list** is defined as a contiguous slice into this concatenated object.
This avoids the storage overhead of multiple `DATA_FRAME`-compatible objects, which may be significant if each object is very small.

## Object metadata

The `OBJECT` file should contain a `data_frame_list` property, itself a JSON object with the following properties:

- `version`, a string specifying the version of the `data_frame_list` format.
  This should be set to "1.0".

## Directory structure

### Contents 

The directory should contain the following:

- `OBJECT`, a JSON file as described above.
- `partitions.h5`, a HDF5 file.
- `concatenated/`, a subdirectory.

Optionally, it may also contain:

- `element_annotations/`, a subdirectory.
- `other_annotations/`, a subdirectory.

### `partitions.h5`

The `partitions.h5` file should contain an `data_frame_list` group.

The `data_frame_list` group should contain a `lengths` dataset.
This dataset should be 1-dimensional and use a datatype that is representable by a 64-bit unsigned integer.
Each entry corresponds to an element of the **atomic vector list** (i.e., a single `DATA_FRAME`-compatible object),
and defines the number of consecutive elements in the `concatenated/` object that can be used to construct each `DATA_FRAME`-compatible object.

Optionally, the `data_frame_list` group may contain `names`, a 1-dimensional string dataset of the same extent as `data_frame_list/lengths`.
The $i$-th entry of this dataset contains the name of the $i$-th entry of the **atomic vector list**.

### `concatenated/`

The `concatenated/` subdirectory should contain a child object that satisfies the `DATA_FRAME` interface.
The height of this child object (i.e., number of rows) should be equal to the sum of lengths in the `data_frame_list/lengths` dataset of the `partitions.h5` file.
This child object represents the concatenation of all entries of the **data frame list**.

The $i$-th entry of the **data frame list** is constructed by taking the slice $[s_i, s_i + l_i)$ from the `concatenated/` object.  
$l_i$ is defined as the $i$-th entry of the `data_frame_list/lengths` dataset in the `partitions.h5` file.
$s_i$ is defined as the sum of $l_j$ for all $j < i$, or zero if $i = 0$.

### `element_annotations/`

The `element_annotations/` subdirectory should contain a child object that satisfies the `DATA_FRAME` interface.
This child object should have number of rows equal to the extent of the `data_frame_list/lengths` dataset in the `partitions.h5` file.
The $i$-th row corresponds to the $i$-th entry of the **data frame list** and contains additional annotations for that entry.

If this subdirectory is absent, no additional additions are available for entries of the **data frame list**.

### `other_annotations/`

The `other_annotations/` subdirectory should contain a child object that satisfies the `SIMPLE_LIST` interface.
This holds extra annotations for the entire **data frame list**.

If this subdirectory is absent, no extra additions are available for the **data frame list**.

## Height

The height of the **data frame list** is defined as the extent of the sole dimension of the `data_frame_list/lengths` dataset in `partitions.h5`.
