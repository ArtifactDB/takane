

# Sequence string set (1.0)

## Overview

The `sequence_string_set` specification describes the on-disk representation of a _sequence string set_.
This is a set of biological sequences (e.g., DNA), possibly with associated quality scores.
It is based on the `XStringSet` class from the [**Biostrings** Bioconductor package](https://bioconductor.org/packages/Biostrings).

## Object metadata

The `OBJECT` file should contain a `sequence_string_set` property, itself a JSON object with the following properties:

- `version`, a string specifying the version of the `sequence_string_set` format.
  This should be set to "1.0".
- `length`, a non-negative integer specifying the number of sequences in the set.
  This property is provided for convenience so that readers do not need to parse the entire FASTA/FASTQ file to determine the size of the string set.
- `sequence_type`, a string specifying the sequence type.
  This should be one of `"DNA"`, `"RNA"`, `"AA"` or `"custom"`.
- (optional) `quality_type`, a string specifying the quality encoding type.
  This should be one of `"none"`, `"phred"` or `"solexa"`.
  If absent, this is assumed to be `"none"`.
- `quality_offset`, a string specifying the offset for quality encodings.
  This should be one of 33 or 64.
  It is only required and used when `quality_type = "phred"`.

## Directory structure

### Contents

The directory should contain:

- `OBJECT`, a JSON file as described above.

If `quality_type = "none"`, the directory should contain:

- `sequences.fasta.gz`, a Gzip-compressed FASTA file.

If `quality_type != "none"`, the directory should contain:

- `sequences.fastq.gz`, a Gzip-compressed FASTQ file.

Optionally, the directory may also contain:

- `element_annotations/`, a subdirectory.
- `other_annotations/`, a subdirectory.

### `sequences.fasta.gz`

The `sequences.fasta.gz` file should follow the [FASTA format](http://ncbi.nlm.nih.gov/genbank/fastaformat/).
The identifier for each sequence should be set to the positional index of that sequence in the file,
e.g., `"0"` for the first sequence, `"1"` for the second sequence, and so on.
The $i$-th sequence in this file represents the $i$-th sequence in the _sequence string set_.

Each sequence should only contain characters from the appropriate alphabet, according to `type`:


- For `"DNA"`, all IUPAC nucleotide codes except U may be used.
  Lower case characters are also supported.
  Gaps may be encoded with `.` or `-`.
- For `"RNA"`, all IUPAC nucleotide codes except T may be used.
  Lower case characters are also supported.
  Gaps may be encoded with `.` or `-`.
- For `"AA"`, all IUPAC amino acid codes may be used.
  Lower case characters are also supported.
  Gaps may be encoded with `.` or `-`.
- For `"custom"`, any ASCII characters may be used.

Sequence strings may contain any number of newlines.
The file must be newline-terminated.
Note that `type = "custom"` should avoid internal newlines in the sequence strings that are followed by `>`, to avoid premature termination of the sequence string. 

The number of sequences should be equal to the `sequence_string_set/length` property in the object metadata.

### `sequences.fastq.gz`

The `sequences.fastq.gz` file should follow the [FASTQ format](https://pmc.ncbi.nlm.nih.gov/articles/PMC2847217/).
The identifier for each sequence should be set to the positional index of that sequence in the file,
e.g., `"0"` for the first sequence, `"1"` for the second sequence, and so on.
The $i$-th sequence in this file represents the $i$-th sequence in the _sequence string set_.

Each sequence string should only contain characters from the appropriate alphabet, according to `type`:


- For `"DNA"`, all IUPAC nucleotide codes except U may be used.
  Lower case characters are also supported.
  Gaps may be encoded with `.` or `-`.
- For `"RNA"`, all IUPAC nucleotide codes except T may be used.
  Lower case characters are also supported.
  Gaps may be encoded with `.` or `-`.
- For `"AA"`, all IUPAC amino acid codes may be used.
  Lower case characters are also supported.
  Gaps may be encoded with `.` or `-`.
- For `"custom"`, any ASCII characters may be used.

Each quality string should only contain ASCII characters within a certain range:

- For `"phred"` with `quality_offset = 33`, the range is `!` to `~` inclusive.
- For `"phred"` with `quality_offset = 64`, the range is `@` to `~` inclusive.
- For `"solexa"`, the range is `;` to `~` inclusive.

Sequence and quality strings may contain any number of newlines.
The file must be newline-terminated.
Note that `type = "custom"` should avoid internal newlines in the sequence strings that are followed by `+`, to avoid premature termination of the sequence string. 

The number of sequences should be equal to the `sequence_string_set/length` property in the object metadata.

### `sequence_annotations/`

The `sequence_annotations/` file contains a child object that satisfies the `DATA_FRAME` interface.
The child object should have number of rows equal to the number of sequences in the FASTA/FASTQ file.
The $i$-th row corresponds to the $i$-th entry of the _sequence string set_ and contains additional annotations for that string.

If this subdirectory is absent, no additional annotations are available for entries of the _sequence string set_.

### `other_annotations/`

The `other_annotations/` file contains a child object that satisfies the `SIMPLE_LIST` interface.
The child object contains extra annotations for the entire _sequence string set_.

If this subdirectory is absent, no extra additions are available for the _sequence string set_.

## Height

The height of a _sequence string set_ is defined as its number of sequences, i.e., the `sequence_string_set/length` property in its object metadata.
