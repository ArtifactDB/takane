

# Atomic vector list (1.0)

## Overview

The `atomic_vector_list` specification describes the on-disk representation of an _atomic vector list_, i.e., a list of _atomic vector_ objects of the same type.
This is based on the `CompressedList` subclasses for atomic vectors, as implemented in the [**IRanges** Bioconductor package](https://bioconductor.org/packages/IRanges).

Here, the central idea is to store a single _atomic vector_ consisting of the concatenation of all entries of the _atomic vector list_.
Each entry of the _atomic vector list_ is defined as a contiguous slice into this concatenated _atomic vector_.
This avoids the storage overhead of multiple _atomic vector_ objects, which may be significant if each object is very small.

## Object metadata

The `OBJECT` file should contain an `atomic_vector_list` property, itself a JSON object with the following properties:

- `version`, a string specifying the version of the `atomic_vector_list` format.
  This should be set to "1.0".

## Directory structure

### Contents 

The directory should contain the following:

- `OBJECT`, a JSON file as described above.
- `partitions.h5`, a HDF5 file.
- `concatenated/`, a subdirectory.

Optionally, it may also contain:

- `element_annotations/`, a subdirectory.
- `other_annotations/`, a subdirectory.

### `partitions.h5`

The `partitions.h5` file should contain an `atomic_vector_list` group.

The `atomic_vector_list` group should contain a `lengths` dataset.
This dataset should be 1-dimensional and use a datatype that is representable by a 64-bit unsigned integer.
Each entry corresponds to an element of the _atomic vector list_ (i.e., a single _atomic vector_),
and defines the number of consecutive elements in the `concatenated/` object that can be used to construct each _atomic vector_.

Optionally, the `atomic_vector_list` group may contain `names`, a 1-dimensional string dataset of the same extent as `atomic_vector_list/lengths`.
The $i$-th entry of this dataset contains the name of the $i$-th entry of the _atomic vector list_.

### `concatenated/`

The `concatenated/` subdirectory should contain a child object that is an [_atomic_vector_](../atomic_vector).
The height of this child object should be equal to the sum of lengths in the `atomic_vector_list/lengths` dataset of the `partitions.h5` file.
This child object represents the concatenation of all of the _atomic vector_ objects in the _atomic vector list_.

The $i$-th entry of the _atomic vector list_ is constructed by taking the slice $[s_i, s_i + l_i)$ from the `concatenated/` child object.  
$l_i$ is defined as the $i$-th entry of the `atomic_vector_list/lengths` dataset in the `partitions.h5` file.
$s_i$ is defined as the sum of $l_j$ for all $j < i$, or zero if $i = 0$.

### `element_annotations/`

The `element_annotations/` subdirectory should contain a child object that satisfies the `DATA_FRAME` interface.
This child object should have number of rows equal to the extent of the `atomic_vector_list/lengths` dataset in the `partitions.h5` file.
The $i$-th row corresponds to the $i$-th entry of the _atomic vector list_ and contains additional annotations for that entry.

If this subdirectory is absent, no additional annotations are available for entries of the _atomic vector list_.

### `other_annotations/`

The `other_annotations/` subdirectory should contain a child object that satisfies the `SIMPLE_LIST` interface.
This holds extra annotations for the entire _atomic vector list_.

If this subdirectory is absent, no extra additions are available for the _atomic vector list_.

## Height

The height of an _atomic vector list_ is defined as the extent of the sole dimension of the `atomic_vector_list/lengths` dataset in `partitions.h5`.
