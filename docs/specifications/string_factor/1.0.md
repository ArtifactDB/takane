

# String factor (1.0)

## Overview

The `string_factor` specification describes an on-disk representation of a **string factor**.
This is based on R's base factor type, also known elsewhere as a category or enumerated type.
It stores an array of "codes" that index into an array of unique strings, i.e., "levels".

## Metadata

The `OBJECT` file should contain a `string_factor` property, which is itself a JSON object with the following properties:

- `version`, a string specifying the version of the `string_factor` format.
  This should be set to "1.0".

## Directory structure

### Contents

The directory should contain the following:

- `OBJECT`, a JSON file as described above.
- `contents.h5`, a HDF5 file.

### `contents.h5`

The `contents.h5` file should contain a `string_factor` group.

The `string_factor` group should contain `levels`, a 1-dimensional string dataset containing the factor levels.
All entries should be unique, and the length of the dataset defines the number of levels.

The `string_factor` group should contain `codes`, a 1-dimensional dataset containing the 0-indexed factor codes. 
The datatype should be representable by a 64-bit unsigned integer.
The $i$-th entry of this dataset is the $i$-th entry of the **string factor**, and serves as an index into the set of levels in `string_factor/levels`.
Thus, entries of this dataset should either be less than the number of levels in `string_factor/levels`,
or equal to the placeholder value if a `missing-value-placeholder` attribute is present.

Optionally, the `string_factor/codes` dataset may contain a `missing-value-placeholder` attribute. 
This attribute should be scalar and have the same datatype as `string_factor/codes`.
All values in the dataset equal to the placeholder should be treated as missing.

Optionally, the `string_factor` group may have an `ordered` attribute.
This should be scalar and use a datatype that fits into a 32-bit signed integer.
If the attribute is present, a non-zero value indicates that the factor levels should be treated as ordered.
Otherwise, the levels are treated as unordered.

Optionally, the `string_factor` group may contain `names`, a 1-dimensional string dataset of the same dimensions as `string_factor/codes`.
The $i$-th entry of this dataset contains the name for the $i$-th entry in the **string factor**

## Height

The height of the **string factor** is defined as the extent of the sole dimension of the `string_factor/codes` dataset in the `contents.h5` file.
