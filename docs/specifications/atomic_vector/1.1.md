

# Atomic vector (1.1)

## Overview

The `atomic_vector` specification describes an on-disk representation of an **atomic vector** from the R programming language.
An **atomic vector** is an array of values of the same "atomic" type, equivalent to a typed array in other languages.
This specification suppports 4 atomic types - integer, boolean, floating-point and string.
(Strings are included here as they are immutable in R.)

## Object metadata

The object metadata in the `OBJECT` file should contain an `atomic_vector` property, which is itself a JSON object with the following properties:

- `version`, a string specifying the version of the `atomic_vector` format.
  This should be set to "1.1".

## Directory structure

### Contents 

The directory should contain the following:

- `OBJECT`, a JSON file as described above.
- `contents.h5`, a HDF5 file.

### `contents.h5`

#### Type specification 

This file should contain an `atomic_vector` group with the following attributes:

- `type`, a scalar string attribute specifying the type of the **atomic vector**.
  This attribute value should be one of `"integer"`, `"boolean"`, `"string"`, `"vls"` or `"number"`.

#### Non-VLS representations

For all `type != "vls"`, the `atomic_vector` group should contain `values`, a 1-dimensional dataset.
Each entry of this dataset represents an entry of the **atomic vector**.
The set of acceptable HDF5 datatypes of this dataset is determined by the value of the `type` attribute:

- For `type = "integer"` or `"boolean"`, the datatype should be representable by a 32-bit signed integer.
- For `type = "number"`, the datatype should be representable by a 64-bit float.
- For `type = "string"`, any valid string datatype can be used.

Optionally, the `atomic_vector/values` dataset may have a `missing-value-placeholder` scalar attribute.
If present, all entries in the dataset equal to the placeholder value should be treated as missing.
The datatype of the attribute should be the same datatype as `atomic_vector/values`, if `type != "string"`;
or any valid string datatype, if `type = "string"`.

Optionally, for `type = "string"`, the `atomic_vector` group may contain a `format` scalar string attribute.
The attribute itself should contain one of the following values:

- `"none"`: no constraints on the contents of each string.
  This is the default behaviour if no `format` is present.
- `"date"`: strings should be dates following a `YYYY-MM-DD` format.
- `"date-time"`: strings should be Internet Date/Time values following the format described in [RFC3339](https://www.rfc-editor.org/rfc/rfc3339).

#### Compressed VLS representation
    
For `type = "vls"`, the **atomic vector** consists of strings stored in a compressed variable length string (CVLS) array.
The `atomic_vector` group should contain: 

- `pointers`, a 1-dimensional dataset using a compound datatype consisting of 2 members, `"offset"` and `"length"`.
  Each member should be of a datatype that can be represented by an unsigned 64-bit integer.
- `heap`, a 1-dimensional dataset of unsigned 8-bit integers.
  This contains bytes from all of the strings in the array, e.g., by concatenating all strings.

The $i$-th entry of the `atomic_vector/pointers` dataset refers to a slice $[o_i, o_i + l_i)$ of the `atomic_vector/heap` dataset,
where $o_i$ and $l_i$ are the values of the offset and length members, respectively.
This slice defines a variable-length UTF-8-encoded string, terminated at the first null in the slice.
If no null character is present within the slice, the string consists of the entire slice. 

Entries of the `atomic_vector/pointers` dataset may be sorted in any order and may refer to overlapping or non-contiguous slices.
The only requirement is that each $[o_i, o_i + l_i)$ slice lies within the boundaries of the heap dataset.

No restrictions are placed on the contents of the `atomic_vector/heap` dataset, as long as the strings can be recovered from slices as described above.
Writers of the `atomic_vector/heap` dataset may concatenate strings in arbitrary order, merge duplicate strings, add padding between strings, etc.
The heap may contain unused bytes, i.e., not referenced by any slice in the `atomic_vector/pointers` dataset.

Optionally, the `atomic_vector/pointers` dataset may contain a `missing-value-placeholder` scalar string attribute.
If this attribute is present, any strings in the CVLS array that are equal to the placeholder should be treated as missing.

#### Names

Optionally, the `atomic_vector` group may contain `names`, a 1-dimensional string dataset of the same dimensions as 
`atomic_vector/values` (for `type != "vls"`) or `atomic_vector/pointers` (for `type == "vls"`).
The $i$-th entry of this dataset contains the name of the $i$-th element in the **atomic vector**.

## Height

The height of the **atomic vector** is defined as the extent of the sole dimension of the 
`atomic_vector/values` dataset (for `type != "vls"`) or `atomic_vector/pointers` dataset (for `type == "vls"`)
in the `contents.h5` file.
