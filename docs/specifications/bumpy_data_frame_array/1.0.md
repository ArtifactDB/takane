

# Bumpy data frame array (1.0)

## Overview

The `bumpy_data_frame_array` specification describes an on-disk representation of a bumpy data frame array.
This is an N-dimensional array where each entry is a data frame (or data frame-like object) with the same type and order of columns.
This is based on the `BumpyMatrix` subclasses for data frames, as implemented in the [**BumpyMatrix** Bioconductor package](https://bioconductor.org/packages/BumpyMatrix).

Here, the central idea is to store a single `DATA_FRAME`-compatible object consisting of the row-wise concatenation of all entries of the bumpy data frame array.
Each entry of the bumpy data frame array is defined as a contiguous row-wise slice into this concatenated object.
This avoids the storage overhead of multiple `DATA_FRAME`-compatible objects, which may be significant if each object is very small.

## Object metadata

The `OBJECT` file should contain a `bumpy_data_frame_array` property, itself a JSON object with the following properties:

- `version`, a string specifying the version of the `bumpy_data_frame_array` format.
  This should be set to "1.0".

## Directory structure

### Contents

The directory should contain:

- `OBJECT`, a JSON file as described above.
- `partitions.h5`, a HDF5 file.
- `concatenated/`, a subdirectory.

### `partitions.h5`

 #### Basic

The `partitions.h5` file should contain a `bumpy_data_frame_array` group.

The `bumpy_data_frame_array` group should contain `dimensions`, a 1-dimensional dataset of any type that is representable by a 64-bit unsigned integer.
This contains the extents of the dimensions of the bumpy data frame array.

The `bumpy_data_frame_array` group should contain `lengths`, a 1-dimensional dataset of any type that is representable by a 64-bit unsigned integer.
Each entry of this dataset corresponds to an entry of the bumpy data frame array (i.e., a single atomic vector),
and defines the number of consecutive elements in the `concatenated` object that should be used to construct each atomic vector.

#### Dense array 

If the `bumpy_data_frame_array` group does not contain an `indices` group, it is assumed that the bumpy data frame array is dense.

The `bumpy_data_frame_array/lengths` dataset should have length equal to the product of the entries of the `bumpy_data_frame_array/dimensions` dataset.

Each entry of the bumpy data frame array maps to an entry of the `bumpy_data_frame_array/lengths` dataset by flattening the former to a 1-dimensional vector.
The first dimension of the bumpy data frame array is the fastest-changing, then the second, and so on.
For example, given a bumpy data frame array of dimensions $(X, Y, Z)$, array entry $(x, y, z)$ would map to entry $x + X(y + Yz)$ of the `bumpy_data_frame_array/lengths` dataset. 

#### Sparse array

If the `bumpy_data_frame_array` group contains an `indices` group, it is assumed that the bumpy data frame array is sparse.

The `bumpy_data_frame_array/indices` group should contain one dataset per dimension.
Specifically, the $d$-th dimension should be represented by the `bumpy_data_frame_array/indices/{d}` dataset.
Each dataset should be a 1-dimensional dataset of length equal to that of the `bumpy_data_frame_array/lengths` dataset.
The datatype should be representable by a 64-bit unsigned integer.

The `bumpy_data_frame_array/indices/d` datasets contain the sparse array coordinates for each entry of the `bumpy_data_frame_array/lengths` dataset.
Given a bumpy matrix of dimensionality $D$, the $i$-th entry of `bumpy_data_frame_array/lengths` would map to the sparse array coordinates $(x_{i0}, x_{i1}, ..., x_{iD})$,
where $x_{id}$ is the $i$-th entry of the `bumpy_data_frame_array/indices/d` dataset.
Entries in each `bumpy_data_frame_array/indices/d` dataset should be less than the extent of the $d$-th dimension.

Sparse array coordinates should be sorted in increasing "reverse-lexicographical" order.
That is, we expect $x_{id} < x_{(i+1)d}$ for at least one $d$ where $x_{if} = x_{(i + 1)f}$ for all $f \in (d+1, ..., D)$.
In other words, the first dimension should contain the fastest-changing coordinates, then the second, and so on.
There should also be no duplicate coordinates.

Aside from the aforementioned datasets, no other objects should be present in the `bumpy_data_frame_array/indices` group.

#### Names

Optionally, the `bumpy_data_frame_array` group may contain a `names` group.
This may contain any number of 1-dimensional string datasets named after the corresponding dimension of the bumpy array,
i.e., the `bumpy_data_frame_array/names/{d}` dataset corresponds to the $d$-th dimension.
If present, each dataset contains the names for its dimension and should have a length equal to the extent of that dimension.

Aside from the aforementioned datasets, no other objects should be present in the `bumpy_data_frame_array/names` group.

### `concatenated/`

The `concatenated/` subdirectory contains a child object that satisfies the `DATA_FRAME` interface.
The height of this child object should be equal to the sum of lengths in the `bumpy_data_frame_array/lengths` dataset of the `partitions.h5` file.
This child object represents the concatenation of all entries of the bumpy data frame array.

Recall that each entry of the bumpy data frame array is represented by an entry of the `bumpy_data_frame_array/lengths` dataset in `partitions.h5`.
To construct the `DATA_FRAME`-compatible object corresponding to the $i$-th entry of the `bumpy_data_frame_array/lengths` dataset,
we take the slice of rows $[s_i, s_i + l_i)$ from the `concatenated/` object.  
$l_i$ is defined as the $i$-th entry of the `bumpy_atomic_array/lengths` dataset.
$s_i$ is defined as the sum of $l_j$ for all $j < i$, or zero if $i = 0$.

## Height

The height of a bumpy data frame array is defined as the extent of the first dimension, as specified in the `bumpy_data_frame_array/dimensions` dataset of the `partitions.h5` file.

## Dimensions

The dimensions of a bumpy data frame array are taken from the `bumpy_data_frame_array/dimensions` dataset of the `partitions.h5` file.
