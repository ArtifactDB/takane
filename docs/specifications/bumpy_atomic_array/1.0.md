

# Bumpy atomic array (1.0)

## Overview

The `bumpy_atomic_array` specification describes an on-disk representation of a _bumpy atomic array_.
This is a N-dimensional array where each entry is an atomic vector of the same type.
It is based on the `BumpyMatrix` subclasses for atomic vectors, as implemented in the [**BumpyMatrix** Bioconductor package](https://bioconductor.org/packages/BumpyMatrix).

Here, the central idea is to store a single _atomic vector_ consisting of the concatenation of all entries of the _bumpy atomic array_.
Each entry of the _bumpy atomic array_ is defined as a contiguous slice into this concatenated _atomic vector_.
This avoids the storage overhead of multiple _atomic vector_ objects, which may be significant if each object is very small.

## Object metadata

The `OBJECT` file should contain a `bumpy_atomic_array` property, itself a JSON object with the following properties:

- `version`, a string specifying the version of the `bumpy_atomic_array` format.
  This should be set to "1.0".

## Directory structure

### Contents

The directory should contain:

- `OBJECT`, a JSON file as described above.
- `partitions.h5`, a HDF5 file.
- `concatenated/`, a subdirectory.

### `partitions.h5`

 #### Basic

The `partitions.h5` file should contain a `bumpy_atomic_array` group.

The `bumpy_atomic_array` group should contain `dimensions`, a 1-dimensional dataset of any type that is representable by a 64-bit unsigned integer.
This contains the extents of the dimensions of the _bumpy atomic array_.

The `bumpy_atomic_array` group should contain `lengths`, a 1-dimensional dataset of any type that is representable by a 64-bit unsigned integer.
Each entry of this dataset corresponds to an entry of the _bumpy atomic array_ (i.e., a single _atomic vector_),
and defines the number of consecutive elements in the `concatenated` object that should be used to construct each _atomic vector_.

#### Dense array 

If the `bumpy_atomic_array` group does not contain an `indices` group, it is assumed that the _bumpy atomic array_ is dense.

The `bumpy_atomic_array/lengths` dataset should have length equal to the product of the entries of the `bumpy_atomic_array/dimensions` dataset.

Each entry of the _bumpy atomic array_ maps to an entry of the `bumpy_atomic_array/lengths` dataset by flattening the former to a 1-dimensional vector.
The first dimension of the _bumpy atomic array_ is the fastest-changing, then the second, and so on.
For example, given a _bumpy atomic array_ of dimensions $(X, Y, Z)$, array entry $(x, y, z)$ would map to entry $x + X(y + Yz)$ of the `bumpy_atomic_array/lengths` dataset. 

#### Sparse array

If the `bumpy_atomic_array` group contains an `indices` group, it is assumed that the _bumpy atomic array_ is sparse.

The `bumpy_atomic_array/indices` group should contain one dataset per dimension.
Specifically, the $d$-th dimension should be represented by the `bumpy_atomic_array/indices/{d}` dataset.
Each dataset should be a 1-dimensional dataset of length equal to that of the `bumpy_atomic_array/lengths` dataset.
The datatype should be representable by a 64-bit unsigned integer.

The `bumpy_atomic_array/indices/d` datasets contain the sparse array coordinates for each entry of the `bumpy_atomic_array/lengths` dataset.
Given a bumpy matrix of dimensionality $D$, the $i$-th entry of `bumpy_atomic_array/lengths` would map to the sparse array coordinates $(x_{i0}, x_{i1}, ..., x_{iD})$,
where $x_{id}$ is the $i$-th entry of the `bumpy_atomic_array/indices/d` dataset.
Entries in each `bumpy_atomic_array/indices/d` dataset should be less than the extent of the $d$-th dimension.

Sparse array coordinates should be sorted in increasing "reverse-lexicographical" order.
That is, we expect $x_{id} < x_{(i+1)d}$ for at least one $d$ where $x_{if} = x_{(i + 1)f}$ for all $f \in (d+1, ..., D)$.
In other words, the first dimension should contain the fastest-changing coordinates, then the second, and so on.
There should also be no duplicate coordinates.

Aside from the aforementioned datasets, no other objects should be present in the `bumpy_atomic_array/indices` group.

#### Names

Optionally, the `bumpy_atomic_array` group may contain a `names` group.
This may contain any number of 1-dimensional string datasets named after the corresponding dimension of the bumpy array,
i.e., the `bumpy_atomic_array/names/{d}` dataset corresponds to the $d$-th dimension.
If present, each dataset contains the names for its dimension and should have a length equal to the extent of that dimension.

Aside from the aforementioned datasets, no other objects should be present in the `bumpy_atomic_array/names` group.

### `concatenated/`

The `concatenated/` subdirectory contains a child object that is an [_atomic_vector_](../atomic_vector).
The height of this child object should be equal to the sum of lengths in the `bumpy_atomic_array/lengths` dataset of the `partitions.h5` file.
This child object represents the concatenation of all of the _atomic vector_ objects in the _bumpy atomic array_.

Recall that each entry of the _bumpy atomic array_ is represented by an entry of the `bumpy_atomic_array/lengths` dataset in `partitions.h5`.
To construct the _atomic vector_ corresponding to the $i$-th entry of the `bumpy_atomic_array/lengths` dataset,
we take the slice $[s_i, s_i + l_i)$ of the `concatenated/` object.  
$l_i$ is defined as the $i$-th entry of the `bumpy_atomic_array/lengths` dataset.
$s_i$ is defined as the sum of $l_j$ for all $j < i$, or zero if $i = 0$.

## Height

The height of a _bumpy atomic array_ is defined as the extent of the first dimension, as specified in the `bumpy_atomic_array/dimensions` dataset of the `partitions.h5` file.

## Dimensions

The dimensions of a _bumpy atomic array_ are taken from the `bumpy_atomic_array/dimensions` dataset of the `partitions.h5` file.
